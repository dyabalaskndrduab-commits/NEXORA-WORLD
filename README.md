# NEXORA WORLD

Android-first 3D social-world foundation built with Kotlin and OpenGL ES 2.0.

## Milestone 0.5.0 — server-authoritative room foundation

The Android client is a local, playable 3D city exploration build with a controllable GLB character, touch joystick, orbit camera, code-driven limb motion, a 140 × 140 city area, avenues, plaza, towers, retail buildings, parks, mall/club landmarks, building collision and a bounded world. Remote movement/camera tuning is loaded from `live-config.json` and cached on device.

**Integration status:** Android now contains register/login, Socket.IO movement and room/chat client code. It still requires a deployed backend URL and two-device testing before it can be considered a verified online game.

## Android build

Android Studio, JDK 17, Android Gradle Plugin 8.7.3 and Gradle 8.9. Build locally with `gradle assembleDebug`. GitHub Actions generates the character GLB, runs tests, builds `app/build/outputs/apk/debug/app-debug.apk` and publishes it as an artifact.

## Character asset

The Android scene loads `app/src/main/assets/NEXORA_Character_v1.glb`, generated by `tools/build_nexora_avatar.py`; named mesh parts are animated by the Android renderer. The separately supplied static GLB still needs an import/texture pass before it can replace this character. No skeletal rig or animation clips are claimed for that separate model.

## Android social client 0.5.0

The Android client now includes:
- Register/login against the backend REST API.
- AES-GCM encrypted access-token storage backed by Android Keystore.
- Socket.IO authentication using the JWT issued by the backend.
- Server snapshots, remote avatar rendering, authoritative position correction, room creation/join/leave, public-room listing and room-scoped chat.
- A small in-game social panel; the game remains playable locally when the player chooses to skip login.

On first launch, open **الحساب** and enter the backend URL. Use a public HTTPS endpoint on a physical phone; `http://10.0.2.2:3000` is only the Android emulator's host-machine alias. No production server URL is configured in this repository.

Movement is sent in normalized 0..1 coordinates derived from the 140 × 140 city. The backend remains authoritative and can return `player:corrected` when a movement update is rejected.

## Backend 0.5.0

The backend has a public plaza and server-owned private rooms, cryptographically random invite codes, capacity checks (2–12), host transfer, empty-room cleanup, room-scoped snapshots/chat and server-side movement bounds/speed validation. Authentication attempts are rate-limited; production requires an explicit strong `JWT_SECRET`.

Accounts, online players and rooms are still in memory, so they disappear when the backend restarts. Android has a client for this Socket.IO protocol, but no production backend is deployed. This remains a development milestone, not a production service. See `backend/README.md`. Run dependency-free tests with `cd backend && npm test`.
