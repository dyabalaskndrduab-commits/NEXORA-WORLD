# NEXORA WORLD

Android-first 3D social-world foundation built with Kotlin and OpenGL ES 2.0.

## Current milestone: 0.5.0 — server-authoritative room foundation

The Android client currently provides a local, playable 3D exploration build:

- Perspective 3D scene with a controllable character rendered from a generated GLB asset.
- Code-driven limb movement for the character's separate mesh parts.
- Touch joystick movement and drag-to-orbit camera controls.
- Expanded 140 × 140 city area with four main avenues and a wider outer road ring.
- Central NEXORA plaza, residential towers, retail buildings, two pocket parks, a mall and a club landmark.
- Building-footprint collision checks and a bounded world area.
- Remote movement/camera tuning loaded from `live-config.json` and cached on the device.

The Android client is still a **single-player local prototype**. It is not yet connected to the backend for accounts, synchronized movement, chat, friends or private rooms.

## Android build

- Android Studio, JDK 17, Android Gradle Plugin 8.7.3 and Gradle 8.9.
- Local debug build: `gradle assembleDebug`.
- GitHub Actions generates the character GLB, runs tests, builds `app/build/outputs/apk/debug/app-debug.apk` and publishes it as a workflow artifact.

## Character asset

The Android scene loads `app/src/main/assets/NEXORA_Character_v1.glb`, generated by `tools/build_nexora_avatar.py`; its named mesh parts are animated by the Android renderer. The separately supplied static GLB still needs an import/texture-compatibility pass before replacing the in-game character. No skeletal rig or animation clips are claimed for that separate model.

## Backend 0.5.0

The backend now has server-owned public/private room membership, cryptographically random invite codes, capacity checks, host transfer, empty-room cleanup, room-scoped snapshots/chat and server-side movement bounds/speed validation. Authentication attempts are rate-limited, and production startup requires a strong explicit `JWT_SECRET`.

Accounts, online players and rooms are still in memory; the Android client is not wired to this Socket.IO protocol yet. This is a development milestone, not a production service. See `backend/README.md`.

Run dependency-free backend tests with `cd backend && npm test`.
