# NEXORA WORLD

Android-first 3D social-world foundation, built with Kotlin and OpenGL ES 2.0.

## Current milestone: 0.4.0 — Expanded city districts

The Android client currently provides a local, playable 3D exploration build:

- Perspective 3D scene with a controllable character rendered from a generated GLB asset.
- Code-driven limb movement for the character's separate mesh parts.
- Touch joystick movement and drag-to-orbit camera controls.
- Expanded 140 × 140 city area with four main avenues and a wider outer road ring.
- Central NEXORA plaza, residential towers, retail buildings, two pocket parks, a mall landmark and a club landmark.
- Building-footprint collision checks and a bounded world area, so the player cannot walk through the main buildings or leave the map.
- Remote movement/camera tuning loaded from `live-config.json` and cached on the device.

The game client is still a **single-player local prototype**. The Android screen does not yet connect to the backend for accounts, synchronized movement, chat, friends, or private rooms.

## Android build

- Android Studio project
- JDK 17
- Android Gradle Plugin 8.7.3
- Gradle 8.9
- Debug build: `gradle assembleDebug`

GitHub Actions generates the character GLB and builds `app/build/outputs/apk/debug/app-debug.apk` on pushes, pull requests, and manual runs. The APK is published as a workflow artifact; it is not committed into the repository.

## Character asset

The Android scene currently loads `app/src/main/assets/NEXORA_Character_v1.glb`, generated by `tools/build_nexora_avatar.py`. Its named mesh parts are animated by the Android renderer.

The separately supplied static GLB model still needs a dedicated import/texture-compatibility pass before it can replace this in-game character. No skeletal rig or animation clips are claimed for that separate model.

## Backend status

See `backend/README.md`. The backend currently contains a starter username/password API and Socket.IO events, but its user records and online state are in memory. Room membership is not yet backed by persistent room records or invite-code authorization, and the Android client is not wired to it. Treat it as development-only; it is not ready for public deployment.
